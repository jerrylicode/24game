# 24Game · 拖拽合成交互原型

> 一句话：把一张牌**拖到**另一张牌上松手，两张牌之间**自动弹出运算符面板**，选 `+ − × ÷`，
> 两张牌飞向中点**撞击消失**，原地**弹出新牌**，其余牌顺势重排 —— 全程有动画和音效。
> 目标：把 4 张牌合成 1 张，结果为 **24**。

零依赖、零构建：**双击 `index.html` 就能玩**，手机浏览器 / 微信 / WebView 里打开同样可用（原生 JS + CSS，音效是 Web Audio 现场合成，不需要任何音频文件）。

---

## 1. 交互设计：为什么是“拖拽合卡”

传统 24 点要先选两张牌，再点运算符，再点确定，四步一循环，节奏碎、反馈弱。
这里把“选两张牌 + 选运算符 + 看结果”压缩成**一次拖拽 + 一次点击**，而且把数学过程直接“物化”成卡牌：

| 设计点 | 做法 | 为什么 |
| --- | --- | --- |
| 合成动作 | 拖 A 落到 B | 物理隐喻：把两个数“压”到一起 |
| 运算符选择 | 松手后自动在**两张牌中点**弹出一圈符号（`+ − × ÷` + 取消），只有符号 | 选择即执行，不提前剧透结果 |
| 方向问题 | 想反过来算（`5 − 7`）就把另一张牌拖过去，左边那张当被减数 | 不需要反向按钮，也不用记顺序 |
| 结果呈现 | 牌面只有一个大点数（牌角是花色），合成来源不画在牌上 | 牌面干净，一眼只看数值；想核对来源悬停有 `title` |
| 纠错 | 撤销 / 重开本关 / 关卡地图 / 三级提示 / 答案面板 / 自动演示 | 卡住时永远有下一步 |
| 兜底交互 | 不想拖的时候，**依次点两张牌**等价于拖拽 | 单手操作 / 无障碍 |
| 推进 | 15 档 × 20 关的**闯关模式**，赢一关解锁下一关，进度存本地 | 有目标、有进度，不是无限换牌 |

### 完整交互时序

```
 ①  按住牌 ── 位移>6px ──▶ 起拖：牌抬起(1.05×)、随指针倾斜、投影变深   ♪ pickup 音
 ②  拖到另一张牌上方 ──▶ 目标牌描边发光 + 轻微放大                    ♪ targetOn 音
 ③  松手落在目标牌上 ──▶ 吸附回位，两牌同时进入“待合成”脉冲态          ♪ snap 音
 ④  两牌中点展开运算符圆环（只有 + − × ÷，除零/非整数等非法运算置灰）   ♪ popupOpen 音
 ⑤  点某个运算符 ──▶ 面板向下收起                                      ♪ choose 音
 ⑥  两牌飞向中点 → 撞击：粒子爆开 + 光环 + 算式飘字 + 桌面震动         ♪ merge 音 + 触感
 ⑦  两牌消失，新牌在原位弹出，其余牌 FLIP 滑动补位                     ♪ spawn 音
 ⑧  判定：只剩 1 张且=24 → 通关；否则若无解立即提示“这条路走不通”      ♪ win / dead 音
```

### 关键状态机（`js/game.js`）

```
idle ──pointerdown──▶ pressing ──>6px──▶ dragging ──drop on card──▶ choosing(弹窗)
                          │                  │                          │
                          │             drop on nothing            选运算符
                          │                  ▼                          ▼
                          └──tap──▶ selected(点选模式)            merging(动画中, busy=true)
                                          │                          │
                                     再点一张牌 ───────────────────────┘
                                                                     ▼
                                                            settling → 结算/判定
```

`busy` 期间屏蔽一切输入，避免“动画还没飞完就又合一次”的错乱。

## 2. 动画编舞（Web Animations API 驱动）

| 阶段 | 时长 | 缓动 | 内容 |
| --- | --- | --- | --- |
| 起拖抬牌 | 即时 | — | `scale(1.05)` + `rotate(±14° 随位移)` + 大投影 |
| 落空回弹 | 440ms | `cubic-bezier(.18,1.5,.4,1)` 回弹 | 从拖拽位移弹回原位 |
| 面板弹出 | 220ms | `cubic-bezier(.22,1.4,.36,1)` | `scale(.86)→1` + 淡入，位置取两牌中点并夹在视口内 |
| 面板收起 | 190ms | ease-out | `scale(.9)` + 淡出 |
| 双牌对撞 | 300ms | `cubic-bezier(.55,0,.35,1)` | 各自朝中点平移 + 反向旋转 ±9° + 缩到 0.62 |
| 撞击瞬间 | 90ms 停顿 | — | 26 粒子爆开 + 光环扩散 + `7 × 5 = 35` 飘字 + 桌面震动 340ms |
| 新牌诞生 | 560ms | `cubic-bezier(.2,1.05,.3,1)` | `scale(.34)→1.13→.97→1` 带过冲，亮度从 2.4 回落到 1 |
| 其余牌重排 | 380ms | `cubic-bezier(.2,.85,.25,1)` | FLIP：先记录旧 rect，DOM 变更后从差值滑回 |
| 换关发牌 | 440ms + 60ms 错落 | 弹入 | 旧牌先旋转飞出，新关的牌依次落下 |
| 通关 "24" 盖章 | 1300ms | `cubic-bezier(.2,1.3,.3,1)` | `scale(2.6)→1` 盖下去再上浮 40px；**面板等它演完（+60ms）才弹**，否则被 z-index 更高的面板盖掉半截 |
| 通关面板 | 300ms | `cubic-bezier(.34,1.56,.64,1)` | 徽章 `24` 用 -46px 负边距骑在卡片上沿：卡片必须 `overflow: visible`，否则上半圈被裁 |

> 尊重系统设置：`prefers-reduced-motion: reduce` 时所有时长自动压到 35%，粒子数量降到约 1/3。

## 3. 音效设计（`js/sfx.js`，全部现场合成）

链路：`振荡器/噪声 → 增益包络 → (可选滤波) → 主输出(压缩器)`，另有一条**延迟反馈混响总线**给胜利音加光泽。
零音频文件，因此可离线、可随动画时长微调，体积为 0。

| 音效 | 配方 | 听感 |
| --- | --- | --- |
| `pickup` 起拖 | 三角波 300→620Hz 130ms + 噪声 2.6k→1.2k | 木头轻响、上滑 |
| `hoverTick` 悬停 | 正弦 1500→1180Hz 45ms | 极轻“嗒” |
| `snap` 吸附 | 方波 520→900Hz 60ms（低通）+ 噪声 | 卡扣声 |
| `release` 落空 | 正弦 620→260Hz 160ms | 泄气回弹 |
| `popupOpen` 弹面板 | 三角 660Hz + 990Hz(延迟 60ms, 混响) | 清脆双音 |
| `choose` 选运算符 | 方波 880Hz 60ms + 1320Hz 30ms 后 | 确认感 |
| `merge` 合成 | 噪声 500→3.6kHz 扫频 + 正弦 170→58Hz 300ms 低音 + 混响闪光 | 呼啸 + 撞击 + 余韵 |
| `spawn` 新牌 | 三角 700→1400Hz + 2100Hz 混响 | 上扬“叮” |
| `invalid` 非法 | 锯齿 220/233Hz 双失谐 + 低通 | 低频“嘟” |
| `undo` 撤销 | 三角 760→340Hz + 噪声反向扫 | 倒带感 |
| `deal` 发牌 | 5 段随机噪声摩擦 | 洗牌 |
| `dead` 死路 | 392→330Hz 与 311→262Hz 下行 | 小二度叹气 |
| `win` 通关 | C-E-G-C-E 琶音（三角波）+ 高八度点缀 + 混响 + 高频扫 | 胜利号角 |

- 首次用户手势才 `AudioContext.resume()`（浏览器自动播放策略）。
- 右上角 🔊 开关，状态存 `localStorage`。
- 移动端关键动作用 `navigator.vibrate` 给触觉反馈。

## 4. 数学与出题的正确性

- **全程精确分数**（`js/fraction.js`）：24 点存在 `8 ÷ (3 − 8 ÷ 3) = 24` 这类必须走分数的解，浮点数判断会出错。
- **求解器**（`js/solver.js`）：DFS 穷举两两配对 × 四种运算（非交换运算两个方向都试），返回完整步骤链，用于
  1) 出题保证有解、2) 三级提示、3) 死路检测、4) 答案面板、5) 自动演示。
- **最小括号**：算式按优先级决定是否加括号，绝不出现 `8 ÷ 3 − 8 ÷ 3` 这种丢括号的错误，也不产生 `((7 + 5))` 多余括号。
- **难度**（`js/dealer.js`）：休闲=1~9 且解法 ≥10 条；标准=1~10 且解法 ≥3；挑战=1~13 且解法 1~4（逼近唯一解）。
- **可选规则**「整数中间值」：打开后每步中间结果必须是整数（`3,3,8,8` 在此规则下直接无解，可用于教学对比）。

几个踩过的坑，都已在代码里解决并留下注释：

1. **命中判定不能依赖 `requestAnimationFrame`**：后台标签页/无头环境可能不产出帧，导致“拖到牌上却没反应”。现在用 pointermove 直接判定，并在 **pointerup 时用松手坐标重新判定落点**。
2. **`animation.finished` 可能永不 resolve**（无合成帧环境），会让 `busy` 卡死整局。统一用 `done(anim, ms)` 做**超时兜底**。
3. **撤销记录结构要一致**：曾经 `history.push(snapshot())` 推数组、`undo()` 读 `entry.cards`，异常被 async 吞掉，表现为“撤销按钮点了没反应”。真机自检抓到了这个 bug。
4. **嵌套算式括号**：先截字符串去括号会把必要括号一起删掉，改为按优先级拼接（并有单测用表达式求值回归）。
5. **界面文案要短，成败都只给结论**：没凑到 24 的面板只显示一张大点数 + “≠ 24”，
   不再复述算式（旧版会把 `7 × 3 = 21` 印出来）也不写解释句；死路/无解只用一句
   “凑不出 24 了”“当前牌面无解”，按钮从“撤销一步”缩成“撤销”。
   通关面板同理：只有 `24` 徽章 + 成绩，没有算式。牌面本身也**不显示任何算式**——
   合成出来的牌只有一个大点数，算式只写进 `title`（桌面悬停可见），
   `aria-label` 里也保留了来源供读屏。自检有三个场景盯这件事
   （面板字数、不得出现 `数 符号 数`、牌面上不得有 `card__expr`）。
6. **落点判定不能只看“最顶层元素”**：被拖的牌是跟着指针走的，`elementFromPoint` 永远返回它自己，
   于是松手永远找不到目标牌、圆环永远弹不出来（表现就是“拖上去没反应”）。现在用 `elementsFromPoint`
   逐层往下找“除自己以外的第一张牌”，并给 `.card.is-dragging` 加 `pointer-events:none` 双保险。
   这个 bug 用合成 PointerEvent 测不出来（虚拟时间下浏览器命中测试不跟随 inline transform），
   所以补了 `tools/input-check.mjs`：用 CDP 发**真实**的鼠标/触摸事件跑拖拽与点击。

## 7. 移动端优先

**基准就是手机竖屏**，桌面是“屏幕变大之后的增强”，不是反过来把桌面版削给手机看。

### 7.1 样式与交互的基准

| 维度 | 基准（手机，无媒体查询） | 什么时候增强、怎么增强 |
| --- | --- | --- |
| 牌桌排布 | **两张一行（2×2）**：棋盘 `max-width` 只留“两张牌 + 一个牌距 + 内边距”，第 3 张必然换行 | `≥721px` 才放开成一行四张（桌面/平板横屏） |
| 卡牌 | 112×159px 兜底，现代内核 `min(152px, (100vw−64)/2, (100vh−275)/2.84)` 自适应 —— 390×844 上牌宽 152px，375×667 上 138px，320×568 上 103px | `≥721px` 固定 104×148（一行四张的手牌尺寸）；横屏 `64×92` |
| 牌距 | 12px | `≥721px` 18/22px |
| 底部工具坞 | 五颗**图标砖**：图标在上、10px 小字在下；中间「关卡」更高、带橙色光晕 | 横屏只剩图标（字会挤），`≥401px` 露出品牌名 |
| 顶部信息 | 两段式：上排 logo + 五个图标工具，下排一条**四格记分牌**（图标 + 数字） | `≥481px` 记分牌拉宽到 620px；`≥721px` logo 放到 40px |
| 运算符面板 | **两牌中点展开的圆环**（参考 Filee 的格式圆环）：圆心是“取消”，四个角上是 `+ − × ÷`，小球错开时间从圆心弹出；**不显示任何运算结果** | 形态不分手机/桌面，只是 `≥721px` 时半径从 76px 放到 92px |
| 手势 | 拖拽 / 点两张牌 / 点圆环外取消，全部为拇指设计 | 鼠标用户额外获得 hover 反馈 |

对应关系是硬约束，用测试锁住（`test/layout.test.mjs`）：

- CSS 里**不允许**再出现给手机打补丁的 `max-width` 查询，只允许 `min-width`、`orientation`、`max-height`、`hover/pointer`、`prefers-reduced-motion`
- 棋盘宽度公式的余量必须**正好**等于“牌距 + 两侧内边距”，多一像素就能塞进第三张
- 牌尺寸必须是 `min(上限, 宽度约束, 高度约束)`，上限 152px、宽高比 1.42；`@supports not (width: min(1px,2px))` 里为老内核留固定兜底
- 圆环只允许 4 个符号 + 取消，`op-btn__res`/`op-btn__swap`/`op-popup` 出现即失败
- 圆环半径 + 小球半径必须 ≤ 安全区，且安全区 × 2 ≤ 320px（窄屏放得下整圈）
- JS 的形态判断（`min-width: 561px` 且非触摸）必须与 CSS 断点一致
- 按视口算账：`390×844 / 414×896 / 430×932` 牌宽 ≥150px 且两行塞得进牌桌；`375×667` ≥130px；`320×568` ≥95px；每档都必须是**两列**（`2×牌宽 + 余量 ≤ 屏宽 − 32`）

> 无头 Chrome 的窗口宽度会被系统钳在 ~500px，所以自检里那些“320/360/390”实际渲染都是 500 宽。
> 真正小于 500px 的排布，由上面这份静态契约测试（解析 CSS + 算账）负责，不靠无头浏览器假装。

### 7.2 移动端坑位

逻辑集中在 `js/h5.js`：

| 问题 | 处理方式 |
| --- | --- |
| 地址栏伸缩/转屏导致 `100vh` 错位，底部按钮被推出屏幕 | `body` 钉死在视口（`position:fixed; inset:0`），`.app` 高度三级兜底：`100%` → `100dvh` → **JS 实测 `--app-h`**（优先 `visualViewport`） |
| 刘海屏 / 灵动岛 / 圆角屏 | `viewport-fit=cover` + `env(safe-area-inset-*)` 上下左右全适配 |
| 旧内核（Android 4.4/5 WebView、部分 X5）**没有 Pointer Events**，拖拽直接失效 | `h5.js` 自动补一层 `PointerEvent`，把 `touchstart/move/end` 翻译成 `pointerdown/move/up`（`pointerdown` 在目标元素上冒泡派发，`move/up` 派发到 window，游戏逻辑一行没改）；原生支持时不安装，避免重复派发 |
| 手指挡住牌，看不见自己拖的是哪张 | 触摸拖拽时牌**上抬 34px**，但**落点判定仍按手指坐标**，目标牌会高亮告诉你会合到谁身上 |
| 双击放大 / 双指缩放 / 长按弹“拷贝-分享”菜单 / 下拉刷新 | `touch-action`、`user-scalable=no`、`gesturestart`/`contextmenu` 拦截、游戏区域内 `touchmove` 不滚动 |
| 横屏手机（如 844×390）上下空间被压死 | 专门的横屏媒体查询：隐藏副标题与统计标签、缩小牌面、收窄按钮；圆环半径同步收到 68px，整圈仍在屏内 |
| 触摸设备上 `:hover` 会“粘住” | 所有 hover 效果收进 `@media (hover: hover) and (pointer: fine)`，触摸设备改用按下态反馈 |
| 手指按不准小按钮 | 触控目标统一 **≥44px**（坞里 52px、中间 64px、顶栏小工具 44px），圆环上的运算符小球本身就有 **56px** |
| 旧内核不支持 CSS `:has()` | 卡牌的“有算式/无算式”不用 `:has()` 分支，避免旧内核样式错乱 |
| 旧内核不认 CSS `inset` 简写（Chrome 87 以下 / X5 常见 66~77） | 全部改成先写 `top/right/bottom/left` 再写 `inset`；`min()/max()` 也都留了定值兜底 |
| 旧内核不支持 flex `gap`（Chrome 84 以下） | `@supports not (gap: 1rem)` 里用 margin 兜底，现代浏览器完全不受影响 |
| 极老内核没有 Web Animations API，`el.animate()` 直接抛错 | 补一个“无动画兜底”：直接落到最后一帧并返回 `finished: Promise.resolve()`，流程照常走完（只是没有过渡效果） |
| 旧内核不支持 `clamp()` / `min()`（X5 66~77） | 牌尺寸先给 `112×159` 定值兜底，再叠一层 `min(152px, …)`；`@supports not (width: min(1px,2px))` 里给矮窗口补小一档，不猜 UA |
| 两牌中点可能贴边，圆环会被切掉 | `positionRing()` 把圆心夹在 `[RING_SAFE, vw/vh - RING_SAFE]` 里（`RING_SAFE` = 半径 + 小球 + 边距 = 132px），只会“挪近一点”，不会缺一角 |
| 圆环要在手指按着的地方弹出（而不是屏幕中央） | 圆心取 `midpoint(两牌)`；`resize`/`scroll`/视口变化都重新夹取，转屏后也不会跑到屏幕外 |
| Safari / 微信需要 `-webkit-` 前缀 | `backdrop-filter` 全部补 `-webkit-`，音频兼容 `webkitAudioContext`，`appearance` / `tap-highlight` 一并处理 |
| iOS 音频要用户手势才能出声 | 首次 `pointerdown` 与 `touchend` 都会 `AudioContext.resume()`，静音偏好存 `localStorage` |
| 软键盘 / 视口变化后弹窗错位 | 监听 `resize` / `orientationchange` / `visualViewport.resize` / `visibilitychange`，圆环圆心重新夹取 |

### 7.3 没有键盘快捷键

这一版面向手机，**键盘快捷键已全部移除**：不再有字母键（`Z/R/N/T/A/M/S/H`）、不再有面板内的 `+ - * /` 与 `Shift` 组合，界面上也不出现任何 `<kbd>` 或“快捷键”提示。

仍然保留两个**不对外宣传**的无障碍行为（不是快捷键，也不占界面）：

- 卡牌获得焦点后可按 `Enter` / `空格` 选中（等价于点一下牌）
- `Esc` 关闭当前浮层（防止弹层把用户困住）

主屏运行：已加 `apple-mobile-web-app-capable` / `mobile-web-app-capable` / `theme-color`，iPhone 上「添加到主屏幕」可全屏无地址栏运行。
调试：`?touch=1` 在桌面强制触摸观感、`?touch=0` 强制鼠标观感、`?debug=1` 面板会显示**视口体检数据**（是否横向溢出、牌桌是否被裁、按钮高度、牌面尺寸）。

## 8. 运算符圆环 · 横屏引导 · PWA · 微信

### 8.1 运算符圆环：两牌中点弹出一圈符号

灵感来自 [Filee](https://filee.sh/zh-cn/#how) 的“格式圆环”——拖动文件落到目标上，就在**光标处**展开一圈可选格式。
这里把 24 点的“选运算符”也做成同一个手势模型：**两张牌一合上，就在两牌中点展开一圈**。

| 位置 | 内容 |
| --- | --- |
| 圆心 | **✕ 取消**（一枚图标，最后弹出） |
| 左上 / 右上 / 右下 / 左下 | `+` `−` `×` `÷` |
| 背后 | 一圈虚线光环，从 0.4 倍撑开 |
| 面板上 | **只有符号**，不显示 `7 × 5 = 35` 这类结果（运算对不对由后续的合卡动画和死路提示来反馈） |

弹出动画（全程 CSS，JS 只负责定位与禁用态）：

| 元素 | 收起态 | 展开态 |
| --- | --- | --- |
| 遮罩 | `opacity: 0` | `opacity: 1`（径向渐变，压暗但牌仍可见） |
| 光环 | `scale(0.4)` | `scale(1)`，0.36s 回弹曲线 |
| 四个小球 | 缩在圆心 `scale(0.35)`、透明 | 飞到各自方位，0.34s `cubic-bezier(.34,1.56,.64,1)` 过冲回弹 |
| 错峰 | — | `--d: 0 / 45 / 90 / 135ms`，一个接一个蹦出来 |
| 取消 | `scale(0.5)` | `scale(1)`，延迟 60ms |

- 点小球 = 选运算符；点**取消**或点**圆环外**（遮罩）= 放弃，两张牌回到原位
- 算不了的符号（比如除以 0）直接置灰，`title` 里写原因
- 左右操作数由**方向**决定：先拖（先点）的那张在左边；想反过来算就把另一张牌拖过去
- 圆心离屏幕边缘太近时整体挪进来（`RING_SAFE = 132px`），不会缺一角

### 8.2 横屏引导

横屏 + 视口高度 ≤ 500px + 触摸设备时才出现一条顶部（横屏时贴底）提示条：

> 📱 *横屏空间有点挤* / 转回竖屏，牌面更大更好拖 —— `[知道了]` `[不再提示]`

- 手机图标带 90° 旋转动画，看一眼就懂
- **整条 `pointer-events: none`**（只有按钮可点），绝不抢拖拽的落点判定
- 12 秒后自动退场；“不再提示”写入 `localStorage`
- 竖屏、桌面浏览器完全不出现（`crampedLandscape` 判定）

### 8.3 PWA：可安装 + 离线可玩

- `manifest.webmanifest`：standalone 显示、`orientation: any`、主题色、**两个快捷方式**（直接开标准局 / 挑战局）
- 图标全部由 `tools/make-icons.mjs` **零依赖现场生成**（自己写的 PNG 编码器 + 5×7 位图字体的 “24”）：192/512 圆角、512 maskable、180 apple-touch、1200×630 分享图，外加 SVG 版本
- `sw.js` 缓存策略：
  - **导航请求** → 网络优先，失败回落到缓存的 `index.html`（断网也能开）
  - **静态资源** → 缓存优先 + 后台静默更新（`stale-while-revalidate`）
  - 跨域 / 非 GET 一律放行；只缓存同源 `basic` 响应
  - 预缓存 18 个文件，**逐个 add**，个别文件 404 不会导致整次安装失败
  - 版本化缓存（`game24-v1.0.0`），`activate` 只清理自己的旧版本，不误伤同域其它应用
- `file://` 或 http 非 localhost 会自动跳过注册，并在调试面板里说明原因（`swError`）
- 安装入口：Chrome / 安卓触发 `beforeinstallprompt` 时顶栏出现「⤓ 安装」图标砖；微信内自动隐藏

### 8.4 微信兼容

| 问题 | 处理 |
| --- | --- |
| iOS 微信里 Web Audio 不出声 | 监听 `WeixinJSBridgeReady` → `AudioContext.resume()`；并用经典的 `WeixinJSBridge.invoke('getNetworkType')` 空调用**预热音频通道**（不这么做首音常被吞） |
| 从后台切回来没声音 | 监听 `visibilitychange`，回到前台补一次 `resume()`（iOS/微信会挂起音频） |
| 微信内没有系统分享面板 | 检测 `MicroMessenger` UA → 弹出**右上角分享引导**（虚线箭头指向 `···`，带上下浮动动画），点击任意处关闭 |
| 微信外的分享 | 优先 `navigator.share()` 系统面板；不支持则 `clipboard.writeText` 复制链接并提示；再不行用 `textarea + execCommand` 兜底 |
| 链接预览卡片 | `og:image` 指向生成的 1200×630 分享图，`og:title/description` 齐全（正式部署建议把 `og:image` 换成绝对地址） |
| 微信内无法安装 PWA | 自动隐藏「安装到桌面」按钮 |

调试开关：`?wx=1` 在桌面浏览器强制微信环境（自检就在用这个验证分享引导）、`?wx=0` 强制非微信、`?sw=off` 关闭 Service Worker 注册。

## 9. 闯关模式：15 档 × 20 关 = 300 关

不是“随便发牌一直玩”，而是一条从幼儿园打到数学之王的路线：

| 档位 | 关卡 | 难度来源 |
| --- | --- | --- |
| 幼儿园 / 小学生 | 1–40 | 只用 + − × 就能算，**只许整数中间值**，数字个位数 |
| 中学生 / 高中生 | 41–80 | 除法登场，解法数开始变少 |
| 大学生 → 副教授 | 81–160 | 一条路走错就绕不回来，解法只剩个位数 |
| 教授 → 图灵 | 161–280 | 分数中间值常驻，最后一段全是“要除以一个式子”的题 |
| 数学之王 | 281–300 | 全库最难的 20 副：`3·3·8·8`、`1·4·5·6`、`1·3·4·6` 这种 |

**关卡表是生成出来的，不是手填的**（`tools/make-levels.mjs` → `js/levels.js`）：

1. 枚举 1–13 的四张牌组合（1820 种），用项目自己的求解器数解法；
2. 按“结构 → 解法数 → 数字大小”打分：只用加减乘 < 要除法 < 必须“除以一个式子”，
   必须用分数再加一档，解法越少越难；
3. 幼儿园取难度队列最前面 20 副，数学之王取最后 20 副，中间 13 档等距抽——
   所以 300 关的难度分严格不降，且**每一关都验证过在本关规则下有解**。

玩法上：

| 环节 | 规则 |
| --- | --- |
| 开始一关 | 每关是**固定牌面**，点关卡徽标或坞里的「关卡」打开地图，点格子进入 |
| 通关 | 通关面板主按钮变成「下一关 →」；横幅上也有同名快捷按钮 |
| 解锁 | 通关一关解锁下一关；没通关的关卡在地图里是灰的、点不动 |
| 档位 | 每 20 关一档，清空一档会播报「🎉 幼儿园 通关 · 下一档「小学生」」 |
| 规则 | 每关自带规则（前两档强制整数，其余允许分数），开局自动套用 |
| 失败 | 「↺ 重开本关」用同一副牌重来，进度不倒退 |
| 存档 | 当前关、已通关数、每关最好成绩都进 `localStorage`，刷新接着打 |
| 展示 | 记分牌第一格是「旗子 + 关号 + 档位」，点它开地图 |

实现上把“关卡”和“发牌”拆开：`setLevel(n)` 只改“我在第几关”（存档、规则、徽标），
`startLevel(n)` = 收起面板 → 设关卡 → 换成这一关的 4 张牌 → 播报「第 N 关 · 档位」；
`nextLevel()` 只在通关后调用。`js/levels.js` 是纯数据，`tools/make-levels.mjs` 可以重跑：

```bash
npm run levels    # 重新生成 300 关（确定性：同样的代码永远同一份关卡表）
```

> 为什么难度不用“解法数少”一条轴：那样 `3·3·3·3` 这种一眼看出的题会被判成最难。
> 先把“要不要除法、要不要把式子当分母”分层，再在层内比解法数和数字大小，
> 出来的曲线才像人排的。

## 10. 视觉设计：明快糖果街机## 10. 视觉设计：明快糖果街机

初版是深绿毛毡 + 金色描边，手机上整体偏沉、像“工具”多于“游戏”。现在整套换成**明快糖果街机**：
浅薄荷纸面 + 白瓷牌砖 + 高饱和糖果色点缀，靠**厚度、回弹、逐帧错落**制造游戏感，而不是靠暗色。

### 10.1 三层结构（每层都要能分开看）

| 层 | 做法 | 目的 |
| --- | --- | --- |
| 纸面 `body` | 奶油底 + 三团径向光晕（薄荷/天蓝/琥珀），两团 `body::before/::after` 26s/34s 缓慢漂移 | 静态画面也有呼吸；只动 `transform/opacity`，不重排 |
| 垫子 `.table__felt` | 浅薄荷底 + 18px 点阵 + 顶部 2px 内高光 + 外投影 | 白牌放上去有“摆上桌面”的层次，不会糊成一片 |
| 牌 `.card` | 近白渐变面 + 左上角高光 + **5px 厚底边** + 落地阴影 | 像实体砖：能拿起来、按下去、落回去 |

### 10.2 配色（每个数字都用 WCAG 算过）

| Token | 值 | 用途 | 对比度 |
| --- | --- | --- | --- |
| `--text` | `#12312a` | 正文 | 13.4:1 on 纸面 |
| `--text-dim` | `#4d6f65` | 次级说明 | 5.6:1 on 白 |
| `--red` | `#d0342e` | 红桃/方块 | 5.0:1 on 白卡 |
| `--ink` | `#0b2a21` | 糖果色上的字/符号 | 8.2:1 on 薄荷 |
| `--mint` | `#17c99a` | 主按钮、选中、`+` | 6.6:1（配 `--ink`） |
| `--coral` | `#ff7a6b` | `−`、警示 | 5.5:1 |
| `--amber` | `#ffc23d` | 提示、`×`、通关 | 8.7:1 |
| `--sky` | `#4aa8ff` | `÷`、焦点环 | 5.6:1 |

四个运算符各配一颗糖果色（薄荷 `+` / 珊瑚 `−` / 琥珀 `×` / 天蓝 `÷`），**颜色本身就是记忆点**；
符号统一用深墨色，亮色球体上也始终 ≥5.4:1，不靠白字硬撑。

### 10.3 手感三件套

1. **厚底边**：按钮/圆环/牌都有一条比本体深一档的实体底边（`box-shadow: 0 Npx 0 <深色>`），一眼知道“能按”。
2. **按下就沉**：`:active` 时 `translateY(3~4px)` + 底边压扁，松手弹回 —— 街机键的手感。
3. **回弹曲线**：所有“出现/选中/弹出”都走 `cubic-bezier(.34,1.56,.64,1)`（过冲 5~10%），
   不出现线性移动；错落延迟让复数元素（发牌、圆环）一个一个到位，而不是整体平移。

### 10.4 风格也能被自检

`?debug=1` 的面板里多了一个只读的 `theme` 探针（设计变量 + 实际计算值），
真机自检里有 4 个场景据此断言：

- 页面底色亮度 > 0.72（不能再是一整块深色），正文 ≥7:1、次级 ≥4.5:1、牌面数字 ≥4.5:1
- 四个糖果色上的符号全部 ≥4.5:1
- 主按钮是“薄荷底 + 墨字”且带 4px 厚底边
- `body::before` 的漂移动画真的在跑，背景是多层 `radial-gradient` 而不是纯色

配套地，`manifest.webmanifest` 的 `background_color/theme_color`、`<meta name="theme-color">`、
iOS 状态栏样式，以及 `tools/make-icons.mjs` 生成的整套图标（薄荷糖底 + 白牌）都跟着换成了明快配色。

### 10.5 图标为主，文字为辅

主界面上没有一句“按钮说明”，全部换成同一套线稿图标（24×24 视框、2.1px 圆头线、跟着 `currentColor` 走），
文字只剩按钮底下的一行 10px 小字，用来兜底：

| 位置 | 图标 | 小字 | 强调色 |
| --- | --- | --- | --- |
| 顶栏 | 三格信号条（点亮到第几档就是第几档难度） | 休闲 / 标准 / 挑战 | 琥珀 |
| 顶栏 | 喇叭（静音时换成带叉的） | 音效 | 薄荷 |
| 顶栏 | 分享箭头 / 下载托盘 / 问号 | 分享 · 安装 · 说明 | 天蓝 / 薄荷 / 灰 |
| 记分牌 | 旗子 · 秒表 · 台阶 · 奖杯 | 只留在 `aria-label`（读屏可读，不占视觉） | 琥珀/薄荷/薄荷/珊瑚 |
| 工具坞 | 撤销 · 重开 · 折地图 · 灯泡 · 清单 | 撤销 · 重开 · **关卡** · 提示 · 答案 | 薄荷/天蓝/橙/琥珀/珊瑚 |
| 圆环圆心 | ✕ | 无（`aria-label="取消这次合成"`） | 灰 |

为什么不用 emoji：跨平台字形差别太大（安卓 Noto、iOS 是彩色字、Windows 是 Segoe），
粗细和配色完全不受控，做不出统一的“街机贴纸”质感；SVG 能跟着文字颜色走、线宽统一、缩放不糊。

规则类的东西（“整数中间值”）不再占主界面，收进「说明」面板里的一个开关（`role="switch"` + `aria-checked`）；
难度也从原生 `<select>` 换成信号条按钮，点一下升一档，档位直接写在图标里。

这些都不是口头约定，`test/layout.test.mjs` 锁死了：主界面 10 个按钮**每个都要有 SVG 图标 + 一行小字**、
不允许出现 emoji 图标、图标统一 2.1px 线宽、关卡地图必须在坞的正中间且更高、横幅要贴在 `--dock-h` 上方。

## 11. 可以继续做的方向

- 联机对战 / 计时排行（当前最佳成绩按难度存在 `localStorage`）。
- 服务端签名的微信 JS-SDK：可自定义分享标题缩略图（纯静态页面做不到，需要后端给签名）。
- 连击与分数系统（合成速度、是否走了最短步数）。
- 更多牌数（5 张凑 24）或“目标数可变”（凑 36、凑 100）。
- 声音主题包（木牌 / 电子 / 硬币），只需换 `sfx.js` 里的合成配方。
